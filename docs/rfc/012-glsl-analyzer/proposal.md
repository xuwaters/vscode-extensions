## 1. Motivation

### 1.1 What exists today

The wgsl-shader extension analyses GLSL with two half-measures stapled together:

- **A heuristic token walk** ([wgsl-syntax/src/parser/glsl.rs](../../../crates/wgsl-shader/wgsl-syntax/src/parser/glsl.rs), 464 lines). It finds declarations by the "name followed by name" signal and produces an outline, scopes and references. It has no grammar, no types, no preprocessor — a `#ifdef` branch is walked as if both sides were live, a macro is a name and nothing more, and an expression is never typed.
- **naga's GLSL front end** for validation. naga implements *Vulkan* GLSL at `#version 440/450/460` only, because it exists to feed wgpu. [analysis/dialect.rs](../../../crates/wgsl-shader/wgsl-lsp-core/src/analysis/dialect.rs) exists solely to detect the sources naga would mangle — OpenGL combined samplers, implicit block bindings, every ES version — and switch validation *off* for them. Commit 64fc05c is the tombstone: "stop flagging OpenGL GLSL as broken" by not analysing it at all.

So the majority of real-world GLSL — OpenGL desktop, WebGL/ES, anything below 440 — gets an outline and nothing else: no diagnostics, no type-aware hover, no real signature help. The builtin tables ([builtins/glsl.rs](../../../crates/wgsl-shader/wgsl-syntax/src/builtins/glsl.rs), 407 lines) are hand-curated one-liners covering one signature per function, no overloads, no version gating, no stage awareness, and a fraction of the ~450 builtin functions and ~100 `gl_*` variables the language actually predeclares.

### 1.2 What "full featured" means here

An analyzer we write ourselves, that answers for **every** GLSL dialect the way naga answers for WGSL:

1. **A real lexer and preprocessor** — macros expanded, conditionals evaluated, with every expanded token still knowing its original byte span.
2. **A real parser** — the GLSL 4.60 grammar (plus ES and legacy variances), producing a lossless syntax tree that survives half-typed input.
3. **Semantic analysis** — scopes, a type model, implicit conversions, constructor and overload resolution, and diagnostics that are true for the dialect the file declares, not for the one naga happens to implement.
4. **A generated builtin spec** — signatures, overloads, real documentation, and per-version/per-stage availability for every builtin function and variable, generated by our own tool from the docs.gl reference pages and embedded as compact Rust tables. The XML/XHTML sources are enormous (tens of MB); the generated tables are not, and only they are committed.

`temp/glslang` and `temp/glsl_analyzer` are the reference implementations to *study* — glslang for what the grammar and semantics actually are (its `Test/` corpus of ~2,000 shaders is also our parser gauntlet), glsl_analyzer for how small an LSP-oriented implementation can stay. We copy neither's code; glsl_analyzer's `spec/gen_spec.py` proves the docs.gl route works and is prior art for the *idea* only.

### 1.3 Why now, and why here

The LSP rewrite (commit bf4e84a) gave the extension a real server core with all features expressed against `wgsl-syntax` + naga. The feature layer is good; the GLSL substrate under it is the weak floor. Replacing the substrate now — while the feature layer is small and freshly tested — is far cheaper than after more features land on the heuristics.

## 2. Goals and non-goals

### Goals

- **G1** — Parse all of: GLSL 1.10–4.60 core, the compatibility-profile declarations that appear in the wild (`attribute`, `varying`, `gl_FragColor`), and GLSL ES 1.00/3.00/3.10/3.20. Zero panics on the glslang `Test/` corpus.
- **G2** — Preprocess for real: `#define`/`#undef` (object- and function-like), `#if` family with constant-expression evaluation, `#version`/`#extension`/`#pragma`/`#line` capture. Provenance from every expanded token back to source bytes.
- **G3** — Type-check expressions and calls: the scalar/vector/matrix/array/struct/opaque type model, implicit conversion rules, constructor semantics, swizzles, and overload resolution against both user functions and the generated builtin spec.
- **G4** — Builtin spec generated from docs.gl by a tool in this repo: every function overload with parameter docs, every `gl_*` variable with its stage, per-version availability (desktop and ES), descriptions as hover-ready markdown. One command regenerates it deterministically; the generated file is committed so diffs are reviewable.
- **G5** — Every existing LSP feature (diagnostics, hover, completion, signature help, definition, references, rename, semantic tokens, symbols, folding, inlay hints) answers from the new pipeline for GLSL documents, in every dialect — not just Vulkan 440+.
- **G6** — Runs where the server runs: inside `wgsl-lsp-wasm`. No filesystem, no threads, no allocation habits that bloat the wasm binary past its budget (see §8).
- **G7** — WGSL behaviour is untouched. naga remains the WGSL authority.

### Non-goals

- **N1** — Not a compiler. No SPIR-V, no codegen, no constant folding beyond what `#if` and array-size checking require.
- **N2** — No `#include` resolution (it is an extension, `GL_GOOGLE_include_directive`); the directive is parsed and tolerated, not followed. Deferred, see §10.
- **N3** — No exhaustive extension modelling. `#extension` declarations are parsed and recorded; gating builtins by individual `GL_ARB_*` extensions beyond what docs.gl encodes is deferred.
- **N4** — No GLSL formatter in this RFC. The existing whitespace-level formatting stays; a real pretty-printer is a follow-up (§10).
- **N5** — Not replacing naga for WGSL, and not deleting the embedded-shader (Rust/TS injection) machinery.

## 3. Architecture

```
                  extensions/wgsl-shader (client + server/main.ts)
                                   │ LSP over wasm boundary
                              wgsl-lsp-wasm
                                   │
                              wgsl-lsp-core
                     (dispatch, state, all features)
                        │                     │
          Language::Wgsl│                     │Language::Glsl
                        ▼                     ▼
            wgsl-syntax + naga          glsl-analysis
            (unchanged)                 (scopes, types, overloads, diagnostics)
                                              │
                                ┌─────────────┴─────────────┐
                                ▼                           ▼
                          glsl-syntax                   glsl-spec
                          (lexer, preprocessor,         (generated builtin tables
                           parser, lossless CST)         + keywords/types, embedded)
                                                            ▲
                                                 generated offline by
                                              glsl-spec-gen (native bin)
                                              from temp/docs.gl clone

          — every crate above lives in crates/wgsl-shader/ —
```

Four new crates joining the three wgsl ones in `crates/wgsl-shader/` (the extension's
grouping directory — explicit workspace members + directory exclude in the root `Cargo.toml`):

| Crate | Ships in wasm | Contents |
| --- | --- | --- |
| `glsl-spec` | yes | The data model for builtins (function, overload, parameter, generic family, version set, stage, variable) plus the **generated** tables and small hand-written tables (keywords, basic types, precision defaults). No dependencies beyond `analyzer-core` if needed. |
| `glsl-spec-gen` | no (dev tool) | Native binary. Reads a docs.gl checkout (`temp/docs.gl`), parses the `sl4/` and `el3/` XHTML pages, emits `glsl-spec/src/generated/*.rs`. Deterministic output, `cargo run -p glsl-spec-gen` is the whole interface. |
| `glsl-syntax` | yes | Token model, lexer, preprocessor (macro table, conditional evaluator, expansion with provenance), recursive-descent parser, lossless CST, error recovery. |
| `glsl-analysis` | yes | Symbol tables and scopes over the CST, the type model, inference, conversion/constructor/overload rules, stage & version gating, the diagnostics catalogue. |

`wgsl-lsp-core` gains a GLSL document pathway: for `Language::Glsl` it builds `glsl-syntax` trees and `glsl-analysis` results instead of the heuristic walk + naga. The heuristic GLSL walk in `wgsl-syntax` is retired for GLSL once feature parity is proven (Phase 5); `dialect.rs`'s skip machinery becomes unnecessary and is removed with a decision record.

### 3.1 The preprocessor is load-bearing

The single biggest correctness gap today. Design constraints:

- **Both sides of a conditional stay visible** to the editor features (an outline must show symbols in the `#else` branch you are editing), but **only the live side is analysed** semantically. The CST therefore keeps inactive regions as trivia-like blocks; analysis runs on the expanded live stream.
- **Provenance is a hard requirement**: every diagnostic, hover and reference lands on real source bytes, including inside macro arguments. Tokens synthesised purely by expansion (the macro body) map to the invocation site.
- Recursion guards and re-expansion rules per the C-preprocessor-derived rules in the GLSL spec §3.3.

### 3.2 The type system, scoped honestly

GLSL's type system is small and closed: scalars (`bool int uint float double`), vectors 2–4 of each, matrices `matCxR` (float/double), arrays (sized/unsized), structs, and ~80 opaque sampler/image/atomic types. No generics, no inference beyond expressions. The hard parts are the *rules*: implicit conversion ranks, constructor legality, component-wise operator semantics, and builtin overloads expressed over generic families (`genType`, `gvec4`, `gsampler2D`). The spec crate encodes families as first-class data so overload resolution can expand them without hand-written per-function code.

### 3.3 The spec pipeline

docs.gl (github.com/BSVino/docs.gl) republishes the Khronos reference pages as one XHTML file per builtin: `sl4/` for desktop GLSL, `el3/` for GLSL ES. Each page carries the prototypes, per-parameter docs, a prose description, and a version-support table. The generator:

1. Reads a docs.gl checkout from `temp/docs.gl` (cloned like the other reference repos; never committed).
2. Parses prototypes into structured overloads (return, name, parameters with types and out/inout qualifiers), keeping generic-family names symbolic.
3. Converts descriptions to hover-ready markdown (strip boilerplate, keep the first meaningful paragraphs, convert entity math), with a per-entry length budget.
4. Merges desktop and ES availability into one entry per builtin with two version masks.
5. Emits sorted, stable Rust `static` tables. Output is committed; CI-style test asserts regeneration is a no-op (when `temp/docs.gl` is present; skipped otherwise).

Details in [design/spec-pipeline.md](design/spec-pipeline.md). Attribution: the reference-page text is Khronos material under open licenses; the generated file carries the attribution header and the extension's third-party notices gain an entry (task P1-10 verifies the exact license and wording).

## 4. Testing strategy

- **The glslang corpus is the parser gauntlet.** `temp/glslang/Test/` holds ~2,000 real shaders spanning every version and stage, including deliberately broken ones. Corpus tests read it *in place* and `skip` when `temp/` is absent (the RFC 011 pattern). Corpus files are never copied into the repo.
- **In-tree unit tests** for everything else — lexer, preprocessor, parser recovery, each conversion/overload rule, each diagnostic with a seeded-error fixture. (House rule: tests are real crate tests, not scratch scripts.)
- **Parity gates** at the integration boundary: before the heuristic walk is retired, the new CST-derived outline must cover everything the old walk found on the extension's `examples/` and the existing `wgsl-lsp-core` feature tests must pass unmodified or with justified snapshot updates.
- **False-positive gate**: a curated list of valid corpus shaders must produce zero error-severity diagnostics. This list starts small and only grows.

## 6. Risks

| Risk | Mitigation |
| --- | --- |
| docs.gl page structure is less uniform than expected (odd prototypes, missing version tables) | P1-01 surveys every page before the generator is designed; the generator fails loudly per-page and the task file records exclusions |
| Preprocessor provenance turns out intricate (macro-in-macro spans) | The rule is fixed up front (§3.1: synthesised tokens map to the invocation); glslang's behaviour is the tie-breaker for observable semantics only |
| Overload resolution subtleties (implicit conversion ranking) cause wrong "no matching overload" errors | The false-positive gate; rules are written from spec §4.1.10/§6.1 with glslang as behavioural oracle on disagreements |
| wasm size grows past budget with ~450 documented builtins | Docs stored as one contiguous `&str` pool with index slices; budget test in P1-09; measured again in P5-10 |
| Two parallel agents touch shared files (root `Cargo.toml`, lock) | All four crate skeletons and workspace entries are scaffolded before execution starts; phase work stays inside its own crate |
| Retiring the heuristic walk regresses embedded-GLSL or edge features | Parity gates in P3-08/P5-01; the walk is deleted only after them, in its own task |

## 7. Alternatives considered

- **Extend naga.** Upstreaming an OpenGL/ES front end into naga is a multi-quarter external negotiation, and naga's IR is a compiler IR — lossy, whole-file, wrong shape for IDE queries. Rejected.
- **Embed glslang via wasm.** Ships a C++ compiler next to a Rust server, double toolchain, no incremental answers, and its diagnostics are compiler-grade, not editor-grade. Rejected.
- **Adopt glsl_analyzer wholesale.** Zig, external process, and the point of this repo's extensions is owning the analysis. It remains the design sanity-check. Rejected.
- **Hand-write the builtin tables.** That is the status quo (407 lines, one signature each); the real surface is ~450 functions × overloads × versions × two profiles with documentation. Only generation keeps it correct and maintainable. Rejected.
- **Parse Khronos OpenGL-Refpages XML directly.** The upstream DocBook XML needs entity resolution and XSLT-era tooling; docs.gl has already flattened it to uniform XHTML. We generate from docs.gl as the user directed. Recorded in [decisions/0002](decisions/0002-docs-gl-as-spec-source.md).

## 9. Success criteria

1. Open a `#version 300 es` fragment shader: real diagnostics, hover on `texture` shows the ES-correct overloads and docs, completion offers `gl_FragCoord` but not `gl_ClipDistance[]`-era desktop-only variables.
2. Open the extension's own `examples/test.frag` (OpenGL-style, combined samplers): validated by *our* analyzer — the "not validated because naga" skip message is gone.
3. A Vulkan 450 shader keeps working end-to-end; WGSL is byte-for-byte unaffected.
4. `rm -rf` the generated file, run the generator, `git diff` is empty.
5. Every phase exit criterion is enforced by a test that exists and is green.

## 10. Deliberately deferred

- `#include` (`GL_GOOGLE_include_directive`) and cross-file analysis.
- Per-extension (`GL_ARB_*`) builtin gating beyond version masks.
- A real GLSL formatter.
- Compute-shader-specific deep checks (local size validation etc.) beyond what the diagnostics catalogue lists.
- Migrating WGSL off naga. Explicitly out of scope forever as far as this RFC is concerned.

## 11. Open questions

Tracked in [decisions/README.md](decisions/README.md); each is closed by a decision record.

1. **naga's GLSL role after Phase 5** — drop the `glsl-in` feature entirely (binary shrinks, one authority), or keep it as optional second opinion for Vulkan-dialect files? Owner: Phase 5. Leaning: drop; the decision record must show diagnostic parity on Vulkan fixtures first.
2. **CST shape** — rowan-style green/red trees vs. the flat event/span arrays used elsewhere in this repo. Owner: P3-01 design doc. Leaning: flat arrays, consistent with the house style and cheaper in wasm.
3. **How much of the compatibility profile** — full legacy builtin set (`gl_ModelViewMatrix` …) or the pragmatic subset the corpus actually uses? Owner: P4-07, informed by P1-01's survey of what docs.gl even documents.
