# 0002 — docs.gl is the builtin-spec source; generated tables are committed

**Status:** Accepted (at RFC acceptance)

## Decision

The builtin function/variable spec is generated by `glsl-spec-gen` from a local checkout
of docs.gl (github.com/BSVino/docs.gl) at `temp/docs.gl` — `sl4/` for desktop GLSL,
`el3/` for GLSL ES. The generator emits deterministic Rust `static` tables into
`glsl-spec/src/generated/`, which are **committed**. The docs.gl checkout itself is not:
`temp/` is already the home for uncommitted reference material.

## Why

- The user's direction, and the right call: the upstream Khronos OpenGL-Refpages are
  DocBook XML with entity soup, tens of MB, and need XSLT-era tooling. docs.gl has
  already flattened them into one uniform XHTML page per builtin with prototypes,
  parameter docs, and a version-support table — exactly the fields the spec needs.
- Hand-maintained tables (the status quo) cannot honestly cover ~450 functions ×
  overloads × versions × two profiles with documentation.
- Committing generated output keeps wasm builds hermetic (no network, no Python, no
  docs.gl checkout needed to build), makes every regeneration reviewable as a diff, and
  matches the repo's convention (fast-html-data, RFC 011).
- glsl_analyzer's `spec/gen_spec.py` is prior art proving the docs.gl route yields a
  complete spec. We take the idea, not the code: our generator is Rust, in-workspace,
  and emits Rust tables rather than a runtime-loaded JSON.

## Consequences

- A determinism test regenerates and diffs when `temp/docs.gl` exists; skipped otherwise.
- Keywords, basic types and precision defaults are *not* scraped (glsl_analyzer scrapes
  the spec HTML for them); they are small, closed sets, hand-written in `glsl-spec` from
  the specification text.
- Attribution for Khronos refpage prose is owed; q4 (P1-10) settles the exact notice.
