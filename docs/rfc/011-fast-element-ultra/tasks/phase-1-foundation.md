# Phase 1 — Foundation

**Goal**: the parser, the WASM artifact, and a plugin skeleton that actually loads.
**Exit criterion**: an installed VSIX whose plugin is loaded by a real tsserver and whose engine
parses a template — and a parser that matches parse5 on the corpus.
**Status**: ☐ 0 / 10

This phase contains no user-visible feature on purpose. It contains the two questions that can
invalidate the design, and answering them first is cheaper than answering them in Phase 4.

## Notes

**P1-09 comes first in practice, even though it is ninth in the list.** It needs only P1-01 and a
stub plugin, and its answer decides whether the rest of the phase is worth starting. If all three
fallbacks fail, stop and reopen [0001](../decisions/0001-tsserver-plugin-not-lsp.md).

**P1-05 gates Phase 2, not Phase 1.** The parser can be finished while the differential harness is
being written; what must not happen is building the registry and the rules on a parser whose
correctness is unestablished.

**P1-07 is the condition on which [0006](../decisions/0006-wasm-inside-tsserver.md) rests.** Running
WASM inside tsserver is only acceptable because a panic degrades to "TypeScript, unmodified". A test
that asserts that is not optional, and it needs to fail loudly if someone later adds an entry point
without the wrapper.
